Cambridge web theme

A shared visual identity for internally hosted services — the colour, type and component styling worked out on mf-service, packaged for reuse. Ships as a Bootstrap 5 theme and as framework-agnostic CSS, generated from the same token file.

This is not an official University of Cambridge design system. It's one team's reading of the brand guidelines, checked against how two departmental sites apply them (phy.cam.ac.uk, mus.cam.ac.uk) rather than the guidelines in isolation. Direct fetches to those sites were blocked in the sandbox this was built in, so the read on their structure came from a screenshot the requester supplied partway through, not a systematic survey — treat this as a considered starting point, not a verified reproduction. If you're building something that needs to match precisely, look at the live sites yourself.

Quickstart

Using Bootstrap

<link rel="stylesheet"
      href="cms-web-theme/dist/cambridge-theme.css">

A full Bootstrap 5 build with the tokens already applied. Link this instead of bootstrap.css, not alongside it. Use Bootstrap's own classes (.btn, .navbar, .card…) plus the handful of .cam-* and -cambridge additions below.

No Bootstrap, no build step

<link rel="stylesheet"
      href="cms-web-theme/css/cambridge-tokens.css">

CSS custom properties (--cam-*) plus a small set of namespaced component classes (.cam-btn, .cam-card, .cam-nav-link…). Nothing to compile.

Both add the same Google Fonts link (Open Sans + Source Serif 4) — see README.md for the exact <link> tag and why those two faces.

Colour

Pantone 547 (--cam-ink) is the dominant colour — text, headings, buttons, nav. Pantone 326 (--cam-teal) is the one accent, used at low density: a header rule, an active underline, a notice's edge. It is never a text or fill colour on its own — both directions fail contrast (see table). This mirrors how phy.cam.ac.uk and mus.cam.ac.uk actually use colour: close to monochrome, not the six-colour brand palette applied broadly.

Categorical palette — status & charts only

The full six-colour primary palette. Reserved for data that needs colour to carry meaning — HTTP status codes, job states, chart series — never used decoratively. Raw brand hexes are too light for white text at AA; each has a darkened companion shade below it.

Science Blue, darkened#005a9e 7.1:1 white text
Vida Loca#55a51c 3.1:1 white text — too light

Every ratio above was computed against the actual hex pairs (relative luminance / WCAG contrast formula), not estimated. The shipped chart palette in tokens.json deliberately skips Vida Loca and Pacific Blue — they sit too close to Science Blue and each other for colour-blind readers to tell apart in a stacked chart; it uses Science Blue, Tango and Purple Heart instead.

Typography

Two faces, per the brand guidelines: Open Sans for body text and UI chrome, Source Serif 4 for headings and the wordmark. Source Serif 4 stands in for Feijoa — the guideline's actual display serif — which is a commercial Klim Type Foundry face with no free web-embeddable licence. If your organisation has a Feijoa licence, swap --cam-font-serif and you're done; nothing else references the face by name. 

<link href="https://fonts.googleapis.com/css2?family=Open+Sans:ital,wght@0,400;0,500;0,600;0,700;1,400&family=Source+Serif+4:opsz,wght@8..60,560;8..60,600&display=swap" rel="stylesheet">

Header — two compositions

Which one to reach for depends on what the header's job is on that page, not on which one looks "more branded."

.cam-header — one row, for an app or tool

Wordmark, then nav links, then right-aligned account actions — separated from the page body by a single 3px accent rule. Nothing else. This is what mf-service uses: its header's only job is navigation, and the real content — a file picker, a dashboard — starts immediately underneath.

Do keep it to that one job when the page itself is a tool. Two early drafts of this composition tried a full masthead band and a hero underneath it, on mf-service specifically — both were pulled after review: for a small internal tool, they read as over-branded and pushed real content below the fold for no benefit.
Don't add a coloured bar, gradient, or block pattern across the top purely as decoration. An early draft built a six-colour block bar from the full primary palette because it looked "Cambridge-branded" — neither phy.cam.ac.uk nor mus.cam.ac.uk has anything like it. If a swatch of colour doesn't correspond to something (an accent rule, a status), it doesn't belong.

.cam-masthead + .cam-hero — for a content or marketing page

An identity band, then a title band underneath — modelled directly on how phy.cam.ac.uk and mus.cam.ac.uk open their own homepages. Use it when the page itself has something to introduce: a homepage, an about page, a project site. See examples/content-page.html.

.cam-hero-deep is the strong, full-bleed Pantone 547 variant (the Cavendish Laboratory's homepage does this). Drop it for the plain .cam-hero (a pale fill) on any page that isn't that one strong homepage moment — every page doing the deep version reads as decoration rather than a statement.

Provenance

This theme was extracted from mf-service after several iterations: a first pass applied the brand's colour and type facts directly and over-produced (a decorative colour bar, Science-Blue-as-dominant, coloured rules under every heading); a second pass, checked against real screenshots of phy.cam.ac.uk and mus.cam.ac.uk, corrected course toward the close-to-monochrome, ink + single-accent look this theme ships; a third pass pared a masthead and hero band back out of mf-service specifically, once they read as over-branded in context on that particular small tool.

A fourth pass then ported mf-service's own, by-then-settled page onto this package as a check that the two actually matched — not by eye, by diffing rendered pixels and computed styles. They didn't, at first: a stray p { line-height: 1.55 } fought the app's own 1.5 and drifted the whole page down by degrees; an unreset h1 margin let the browser's own em-relative default back in once the heading's font-size changed; the wordmark link was a few px short of the original because that original had picked up padding and a border incidentally, from also matching a broader nav-link selector. All three are fixed in what ships now. That same pass also broadened the theme past mf-service's own shape — .cam-masthead, .cam-hero and .cam-prose exist because "a single-row header and no content typography" was a reasonable shape for mf-service, not a reasonable ceiling for "a site" in general.

Nothing here should be treated as verified against the University's own design system — it's a considered, iterated approximation, not a specification. If you use this on a site that isn't an official University of Cambridge page, say so somewhere the reader will see it — a judgement call per site, not a rule this theme enforces.
