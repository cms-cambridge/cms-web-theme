Cambridge web theme

Colour, type and component styling for internally hosted services, worked out on mf-service and packaged for reuse. A Bootstrap 5 theme and framework-agnostic CSS, from one token file.

Not an official University of Cambridge design system. One team's reading of the brand guidelines, checked against how phy.cam.ac.uk and mus.cam.ac.uk apply them. Direct fetches to those sites were blocked while this was built, so that check came from a screenshot, not a survey. If you need to match precisely, look at the live sites.

Quickstart

Using Bootstrap

<link rel="stylesheet"
      href="cms-web-theme/dist/cambridge-theme.css">

Bootstrap 5 build with the tokens applied. Link it instead of bootstrap.css. Use Bootstrap's classes plus the .cam-* and -cambridge additions below.

No Bootstrap, no build step

<link rel="stylesheet"
      href="cms-web-theme/css/cambridge-tokens.css">

Custom properties (--cam-*) and a small set of .cam-* classes. Nothing to compile.

Both need the Google Fonts link (Open Sans + Source Serif 4); see README.md.

Colour

Pantone 547 (--cam-ink) is the dominant colour: text, headings, buttons, nav. The logo's light blue (--cam-accent) is the one accent, used thin: a header rule, an active underline, a notice's edge. On a light page it is never text or fill on its own; both directions fail contrast. This mirrors how phy.cam.ac.uk and mus.cam.ac.uk use colour: near-monochrome, not the full six-colour palette.

Ratios computed from the hex pairs (WCAG formula). The chart palette skips Vida Loca and Pacific Blue, which sit too close to Science Blue and each other for colour-blind readers; it uses Science Blue, Tango and Purple Heart.

Dark mode — prototype

Try the toggle in the header. The vanilla build follows the OS on its own; the toggle overrides it and remembers the choice. Tokens flip, so components don't know which mode they're in, except in three places.

The navy moves from text to surface: --cam-ink means "text and primary control", so it goes pale. The logo blue needs no change; it clears 6:1 on these surfaces.

Where a token flip isn't enough

  • The primary button inverts (pale pill, dark text), since navy would vanish into a navy surface. Hence --cam-on-ink instead of #fff.
  • The deep hero keeps its navy, via --cam-deep, since --cam-ink is now pale. White text in both modes.
  • Images can't read tokens. The select chevron and checkbox tick have dark twin rules; the logo needs assets/cms-mark-dark.svg. Show one per mode with .cam-only-light / .cam-only-dark.

Unchanged on purpose: the categorical badges, and --cam-danger, which as a badge fill must keep holding white text. As a 3px edge it reads 2.9:1, just under the 3:1 non-text bar.

</button>

The button ships hidden and the script reveals it, so without JavaScript there's no dead control and the OS decides. The script sets <html data-theme="light|dark">, the only thing the CSS reads, so a toggle of your own can set it.

The Bootstrap build uses Bootstrap 5.3's data-bs-theme="dark" with this palette in place of its greys. The script sets it too, so both columns below follow the toggle. Without the script, set it yourself: this build doesn't read the OS.

Typography

Two faces, per the brand guidelines: Open Sans for body and UI, Source Serif 4 for headings and the wordmark. Source Serif 4 stands in for Feijoa, the guidelines' display serif, a commercial face from Klim Type Foundry.

The University licenses Feijoa for staff (typography guidance, brand resources), but a licence to use a font isn't necessarily one to serve it as a webfont. Check the terms and the brand team before using it on a public site. If cleared, change --cam-font-serif and add your @font-face. 

<link href="https://fonts.googleapis.com/css2?family=Open+Sans:ital,wght@0,400;0,500;0,600;0,700;1,400&family=Source+Serif+4:opsz,wght@8..60,560;8..60,600&display=swap" rel="stylesheet">

Header — two compositions

Pick by the header's job on that page, not by which looks more branded.

.cam-header — one row, for an app or tool

Wordmark, nav links and right-aligned actions, under one 3px accent rule. This is mf-service's header: it only navigates.

Do keep it to that job when the page is a tool. Early drafts added a masthead and hero to mf-service; both were pulled as over-branded.
Don't add a coloured bar, gradient or block pattern as decoration. Neither phy.cam.ac.uk nor mus.cam.ac.uk has one; colour should mean something (an accent rule, a status).

.cam-masthead + .cam-hero — for a content or marketing page

An identity band, then a title band, modelled on phy.cam.ac.uk and mus.cam.ac.uk. For a page with something to introduce; see examples/content-page.html.

Modal

One panel over a blurred page: a welcome box, a first-run explainer, a short confirm. Built on <dialog> and showModal(), so the browser supplies the top layer, focus trap, inert page and Escape; ::backdrop carries the blur. Same class names in both builds; only the button and checkbox inside differ (.cam-btn and a bare checkbox in vanilla, .btn and .form-check-input in Bootstrap).

Do put autofocus on the primary button. Otherwise showModal() focuses the close ✕ first.
Don't use it for a form, a settings panel or navigation. A modal interrupts, so keep it short enough to read standing up. Bootstrap's own .modal is better when you want its JS API or a full-width sheet on small screens. 
<dialog class="cam-modal" aria-labelledby="welcome-title">
  <div class="cam-modal-head">
    <div>
      <p class="cam-modal-kicker">Welcome</p>
      <h2 class="cam-modal-title" id="welcome-title">Welcome to <em class="cam-brand">Example Service</em></h2>
    </div>
    <button type="button" class="cam-modal-close" aria-label="Close"><svg …></svg></button>
  </div>
  <p class="cam-modal-lede">One sentence on what this page is for.</p>
  <ol class="cam-modal-steps">
    <li class="cam-modal-step"><span class="cam-modal-step-mark">1</span><span>First thing.</span></li>
  </ol>
  <div class="cam-modal-actions">
    <button type="button" class="cam-btn" autofocus>Get started</button>
    <label class="cam-modal-opt"><input type="checkbox"> Don't show this again</label>
  </div>
</dialog>

el.showModal();   // not el.show() — that opens it with no backdrop,
                  // no focus trap and no inert page, so the blur
                  // silently never appears.

Provenance

Extracted from mf-service over several passes. The first over-produced (a colour bar, Science Blue as dominant, coloured heading rules); the second, checked against screenshots of phy.cam.ac.uk and mus.cam.ac.uk, corrected to near-monochrome: ink plus one accent. Later passes pared the masthead and hero out of mf-service itself, added them here for content pages, and fixed spacing drift found by diffing rendered pixels against mf-service (a stray line-height, an unreset h1 margin, wordmark padding).

Nothing here is verified against the University's own design system. If you use it on a site that isn't an official University page, say so somewhere the reader will see it.
